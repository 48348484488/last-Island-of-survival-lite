Actual native ARM64 artifact:

The standalone diagnostic APK was compiled and signed, then installed
alongside **all four unchanged original Oxide 1.14.11949 splits** in the
same Android 13 ARM64 container. The original game Activity remained
top-resumed while the overlay was captured (game PID **2176** present at
all three capture checkpoints).

The second original-game screenshot (overlay_on_game_2.png, 1280x720)
clearly shows:
- Original Oxide tower / landscape loading artwork;
- Green controlled diagnostic rectangle in the center, bounds
  [535,287,744,432], with **2,416 green pixels**;
- Diagnostic text "DIAGNOSTIC OVERLAY - NO GAME DATA" near the top;
- Unmodified original game's "Security Threat Detected by App" toast.

Following stop of the diagnostic overlay service, the portrait
overlay_removed.png screenshot had **zero** diagnostic green pixels.
The checker returned **ORIGINAL_LOADING_OVERLAY_PASS**, and all five
screen/pixel classification regressions passed in the ARM64 job.

The original game, however, still closed under its own security logic:
PID **2176** logged a self-directed SIGKILL at **22:14:23.520 UTC**
(see forensic_summary.json in the Actions artifact). Neither game
multiplayer nor real player-coordinate acquisition was tested.

Thus the goal achieved by this run is strictly **window compositing of
a controlled diagnostic overlay over the original game's loading
Activity**. It is not a player ESP, does not imply crash-free operation,
and does not identify or bypass the original security check.

Next blockers for a true gameplay system: original app must legitimately
reach an active multiplayer session; a permitted source must supply
the actual camera matrices, entity IDs, and timestamped player positions.
