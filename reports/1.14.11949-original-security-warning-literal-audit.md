## Security warning displayed during original native ARM64 boot

The original unmodified Oxide Redroid Android 13 ARM64 screenshot
from [run #38468783338](https://github.com/48348484488/oxide/actions/runs/38468783338)
visibly contained:

    REF: 5600:AA4C:C5CMCO Security Threat Detected by App

In that unrelated baseline original-game run, the Oxide Activity loaded,
then its process self-directed SIGKILL, without changing the original APK
or running the independent ESP overlay. A message in a screenshot is
runtime evidence of display, not evidence of which static binary owns
the string or which environment property caused a protection decision.

## Other settled technical evidence

- x86_64 official Android Google Play emulator (API 34/35/36):
  an independent ARM64 MRS register read reproduced SIGILL in each image.
  [Version comparison #38485084410](https://github.com/48348484488/oxide/actions/runs/38485084410)
  passed both AVD jobs, meaning the *diagnostic completed*, not that
  the instruction was supported.
- The **original game's x86 translated crash** was traced to Berberis
  reporting the matching undefined instruction before SIGILL.
  [13-test direct verification #38484496716](https://github.com/48348484488/oxide/actions/runs/38484496716).
- Native Android ARM64 executes the MRS register read normally in the
  **isolated diagnostic APK**; the original Oxide game gets further into
  Unity initialization but self-terminates by SIGKILL.
- All four ordinary Android runtime permissions were granted in one
  native ARM64 trial, and the original game still self-terminated.

## Current engineering boundary

The original app's reason for rejecting this untrusted native virtual
Android environment is **not identified**. A standalone green diagnostic
overlay was demonstrated over the real game's **loading screen**; no
multiplayer session or real player-position source has been established.
This audit neither weakens app security checks nor supplies such data.

The next decisive environment experiment requires an **authorized
Google-Play-supported native ARM64 Android device** (potentially a
remote physical device service) able to install the authentic game's
splits normally and provide permitted ADB evidence. It cannot be
replaced with more Android app permission grants or by renaming
an emulator model. Any device-integrity verdict would require official
attestation and is not assumed from Google app package presence.
