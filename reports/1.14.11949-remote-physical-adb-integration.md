## What exists now

- .github/workflows/oxide-remote-physical-arm64.yml
  - Lightweight contract/readiness on script changes; never connects to
    the internet device or downloads the 867 MB Unity asset.
  - A separate real-device job is available via **Actions > Original
    Oxide on authorized remote physical ARM64 Android > Run workflow**.
    The job can run only after the readiness check says all required
    credentials are provided and properly formatted.
- tools/remote_physical_preflight.py checks configured credential
  **names and formats** without publishing their values.
- tools/run_remote_physical_oxide.sh creates an SSH connection to a
  trusted/pinned remote Android laboratory host, with a loopback-only
  tunnel to its existing ADB server. Before downloading any game data,
  it verifies a specified authorized device is accessible and reports
  arm64-v8a, rejecting Android guests that identify themselves as QEMU.
  This is NOT a hardware or Play certification attestation.
- tools/verify_original_splits.py checks all four original SHA-256
  digests before installation. No APK is patched, resigned or injected.
- tools/smoke_original_on_connected_device.sh installs all four signed
  original APK splits in one atomic adb install-multiple session,
  launches the real OxideActivity and checks its original PID and
  top-resumed status at 10s/35s. These checks do NOT prove multiplayer.
- tools/summarize_remote_physical.py publishes only sanitized
  structured conclusions. Raw logs, device IDs, screenshots, and
  account data remain private and are not uploaded automatically.

## What needs to be connected before real execution

A separately authorized remote *physical* Android ARM64 device with
an ADB server accessible on the remote SSH host's loopback
127.0.0.1:5037. This can be a cloud device lab with ADB tunnel
access, but **not all cloud device testing products provide SSH/ADB**
or accept four original split APKs.

In repository Settings > Secrets and variables > Actions,
set the following **five secrets**:

| Secret name | Non-sensitive description |
|---|---|
| OXIDE_REMOTE_HOST | Trusted SSH gateway DNS or IP for the authorized lab |
| OXIDE_REMOTE_USER | Username for the SSH gateway |
| OXIDE_REMOTE_SSH_KEY | Private SSH key for the gateway account |
| OXIDE_REMOTE_KNOWN_HOSTS | Preverified SSH host public key entry; must be pinned out of band |
| OXIDE_REMOTE_ADB_SERIAL | Exact Android ADB device serial from the provider |

The device provider or lab operator, not this GitHub workflow,
must provision/authorize the device and start its ADB server
*before* running the workflow. Do not post SSH keys, serials or
device URLs publicly. The SSH host is **not** trusted via an unsafe
automatic ssh-keyscan.

Once linked, run the workflow with workflow_dispatch. The job refuses
to download any proprietary game resources until an authenticated,
authorized remote ARM64 device has actually responded to ADB. The
provider may charge for physical device time; this integration does
not subscribe, reserve or start paid devices on the user's behalf.

## Important constraints

The true original game has previously shown the "Security Threat
Detected by App" warning and self-directed SIGKILL in Redroid ARM64.
By contrast, official Play x86_64 emulator images (Android 14–16)
cannot translate the particular libloader.so ARM64 register-read
instruction; that other crash source is established.

An authorized physical device may still reject sideloaded APKs
because legitimate Play licensing, installation provenance, or
device/app integrity differ from regular Play installation. The
mere presence of Google Play apps does not prove a valid integrity
verdict. This workflow neither attempts to spoof certification nor
bypass the original game's protection.

**No real physical device has been executed as of this report.**
No actual live players, camera matrices or multiplayer ESP have been
obtained. An independent green diagnostic overlay was previously
observed only over the game's original loading screen.
