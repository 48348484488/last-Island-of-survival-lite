# Oxide 1.15.11966 — exceção Android de permissão em API pública (evidência original)

**Data da análise:** 16/10/2026. **Escopo:** apenas `aapt dump badging` e `logcat` originalmente capturados nos Redroid Android 15/16 com os quatro APKs **inalterados**. Nenhum APK, assinatura, permissão do dispositivo ou mecanismo de proteção foi alterado.

## Incompatibilidade reproduzível de contrato Android

Os dois registros originais mostram o mesmo erro Java do processo que iniciou `com.catsbit.oxidesurvivalisland/.OxideActivity`:

```text
Caused by: java.lang.SecurityException: Need to declare android.permission.REQUEST_INSTALL_PACKAGES to call this api
at android.app.ApplicationPackageManager.canRequestPackageInstalls(...)
```

O `aapt dump badging` original contém `targetSdkVersion:'36'` e **não apresenta** `uses-permission: name='android.permission.REQUEST_INSTALL_PACKAGES'`.

A [documentação oficial do PackageManager.canRequestPackageInstalls()](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls()) exige que aplicativos voltados ao Android O ou superior **declarem** essa permissão para consultar a API. Logo, a exceção observada é **compatível com o contrato público do SDK**: a chamada foi feita sem a permissão declarada. Isso **não é prova** de limitação de Binder, falha de Play Integrity, anti-cheat, causa do alerta visual ou culpa do Redroid. A permissão é sensível e sua concessão/adição **não é proposta** nesta investigação.

## Decisão técnica

**Diagnóstico verificável do contrato SDK:** há consulta a `canRequestPackageInstalls()` sem a permissão requerida no pacote original, em **ambos** os Androids virtuais ARM64. Isso é uma inconsistência de uso da API que cabe ao desenvolvedor do aplicativo avaliar na origem; não é justificativa para editar/reassinar o jogo, declarar ou conceder permissão, falsificar atestado ou contornar proteção.

**M4 permanece bloqueada:** não existem 35 segundos de Activity e PID originais estáveis, nem menu/gameplay efetivo. O motivo interno do alerta `Security Threat Detected by App` e do `SIGKILL` continua **UNKNOWN**. A exceção antecedente não pode ser apontada como causa. Não repetir inicializações pesadas a partir deste achado.
