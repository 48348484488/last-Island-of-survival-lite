# Oxide 1.14.11949 — camera hierarchy, scripts and runtime boundary

**Evidence:** two successful GitHub Actions static analyses of the original Release:
- Camera owner/reference graph: https://github.com/48348484488/oxide/actions/runs/38458081804
- Camera / MonoScript registry correlation: https://github.com/48348484488/oxide/actions/runs/38458491054

No injected code, no modified APK, no multiplayer traffic or live camera matrix was observed.

## Native cameras and ownership

- `CharacterCamera`: child of `Lobby_NPC`, pointed to by `PreviewCamera` on Lobby_NPC. FOV=38°, near=1, far=3. Character preview, not established as multiplayer camera.
- `Camera` from `shared-world-local`: child of `ItemPreviewScene → CameraController → Camera`. Pointed to by `<Camera>k__BackingField`. FOV=45°, near=0.1, far=10. Item-preview scene, not an active world camera.
- `World Camera` in `scenes-tutorial`: child of `WorldSetUp Tutorial`, native `Camera` at serialized pathID **8848**, FOV=60°, near=0.15, far=2000, perspective projection. Additional MonoBehaviours `Oxide.CameraManager`, `UnityEngine.Rendering.Universal.UniversalAdditionalCameraData`, and `WorldStreamingController`. Serialized `CameraManager.m_Camera` points to native Camera 8848. URP `m_Cameras` on World Camera links the tutorial UI Camera 8847. These are saved tutorial settings, not live multiplayer data.

## Player prefab and script linkage

In `core-common-local`, the `player` prefab has the following Transform parent chain:

    player → Look Root → World Camera Root

The player prefab's `PlayerManager.worldCameraRoot` refers to the native `World Camera Root` Transform, and the Transform GameObject has the C# MonoBehaviour **`Oxide.FPCameraController`** attached (serialized MonoScript pathID `5979656591269764229`).

`Look Root` has **`Oxide.MouseLook`** (`8675533733321387705`) and `Oxide.RootHeightHandler`. `PlayerManager` corresponds to MonoScript pathID `1880262411997230070`.

The `tutorialPlayer Variant` prefab contains the same `Oxide.FPCameraController` and `Oxide.MouseLook` script identities. The player camera root has a native `Transform`, `AudioListener`, and `FPCameraController` MonoBehaviour **but no native Camera component** in either saved prefab.

The MonoScript registry includes **1991 script records**; all 100 monitored MonoBehaviour references matched unique script-path entries. The references use external fileID=1 and must be validated against each bundle's actual external file table before claiming file-level foreign-key integrity (the matching pathID by itself is not sufficient).

## Engineering conclusion

The saved hierarchy identifies the player-facing camera orientation components, while the tutorial scene carries a standalone native world Camera and its CameraManager. There is no proof from these serialized resources that the real multiplayer camera is the same Camera object, or that the server sends hidden enemy positions to the client.

**No in-game ESP currently exists.** The native C++ projection bridge has passed its own Android/JNI stress test, but it is not hooked to the game. Real integration would require a permitted runtime source for the actual active Camera view-projection matrix and relevant player positions, a renderer, and boot/gameplay testing on native ARM64 hardware. Do not distribute an APK claiming crash-free ESP functionality based only on this report.
