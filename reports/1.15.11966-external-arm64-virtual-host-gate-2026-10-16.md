# External ARM64 virtual Android feasibility gate — 2026-10-16

### External ARM64 virtual-host feasibility gate (2026-10-16)

Read-only public documentation review, **no APK download, Android boot, device alteration, or new CI run**:

- Firebase Test Lab documents ARM-suffixed accelerated virtual devices, but explicitly says the Google Play Store app is unsupported on ARM virtual devices. This is not evidence of Play Integrity support or original Oxide compatibility: https://firebase.google.com/docs/test-lab/android/avds
- Sauce Labs documents native ARM Android 14–17 virtual emulators without x86 instruction translation, but ARM access is Enterprise-plan-only with allocated concurrency; it is not an authorized no-payment path: https://docs.saucelabs.com/mobile-apps/android-emulators/
- AOSP Cuttlefish instructions require KVM; existing GitHub ARM64 runner preflights found no usable hypervisor: https://source.android.com/docs/devices/cuttlefish/get-started

**Decision:** no newly verified, accessible ARM64 virtual Android environment meeting project constraints. `heavy_android_or_apk_trial_authorized=false`. Do not repeat boots or APK downloads on these candidates. No claims of 35s same PID, original menu, gameplay, or valid overlay. Reassess only on new documented, accessible host capability plus cheap host preflight. Public documentation establishes platform capabilities, not Oxide compatibility.

## Additional documented exclusion checks (verified 2026-10-16)

- Firebase Test Lab's official AVD documentation lists Arm virtual devices with GPU acceleration, but says the **Google Play Store app is unsupported** on those Arm virtual devices. It also lists **$1 per virtual-device hour**. This is a published product capability and cost, **not** a verified Oxide execution environment. Source: https://firebase.google.com/docs/test-lab/android/avds
- Sauce Labs documents Android ARM emulators on native ARM hardware (Android 14–17), but requires **Enterprise subscription and allocated ARM concurrency**. Its Appium virtual-device documentation additionally states that **Android emulators with Play Store integration are unsupported**. These are distinct constraints: native ARM support alone is insufficient to claim a Google Play-compatible Oxide environment. Sources: https://docs.saucelabs.com/mobile-apps/android-emulators/ and https://docs.saucelabs.com/mobile-apps/automated-testing/appium/virtual-devices/

### Evidence-based stop condition

No accessible, no-new-payment ARM64 virtual Android target with both the required host acceleration and a verified legitimate Google-services configuration was identified. Neither platform was used to install or launch any of the four original APKs. `heavy_android_or_apk_trial_authorized=false` remains mandatory. An external provider marketing claim or a generic ARM64 ABI match is **not** proof of same-Activity/same-PID 35s, original menu, or gameplay. Reopen the selection only with genuinely new official evidence of a usable, authorized host and an inexpensive capability preflight; do not repeat existing Linux ARM64 KVM, Windows ARM64 WHPX, Redroid, or Berberis trials.
