## Experiment

An Android 13 ARM64 native Redroid guest installed all four exact
SHA-256-verified, original signed APK splits. The original Activity
was launched, followed by four ordinary system runtime permission grants,
then a second original Activity launch on the SAME guest. No spoofing,
binary changes, injection, or alteration of security checks.

| Original permission | Before | After |
|---|---|---|
| CAMERA | DENIED | GRANTED |
| RECORD_AUDIO | DENIED | GRANTED |
| BLUETOOTH_CONNECT | DENIED | GRANTED |
| POST_NOTIFICATIONS | DENIED | GRANTED |

Play Services, Play Store and GSF remained absent.

Direct after-grants evidence from the run log:

The Android process exit-info additionally reports PID 2578,
reason SIGNALED and status 9.

## Forensic false negative found and fixed

The initial A/B machine classification incorrectly claimed
INITIAL_ACTIVITY_NO_SELF_SIGKILL_OBSERVED after the permission grants.
The second logcat file included old Android event-buffer rows about PID
2197 (first launch) followed by new rows for PID 2578. The previous
analyzer selected the first old launch instead of the latest launch.
The result was a log parsing bug, NOT a game stability improvement.

Corrections:
- Select the most recent OxideActivity process start; scope subsequent
  finish/death/signal evidence to that launch.
- Clear Android logcat from ALL buffers between attempts.
- Add two regression tests for mixed launches and background services.
- [Fast validation #38479050657](https://github.com/48348484488/oxide/actions/runs/38479050657)
  PASSED 23 Python tests plus script syntax and missing-APK rejection.
  This validates the fixed parser without claiming a second expensive
  Android run.

## Technical conclusion

Four normal runtime permissions are now proven to be accepted and
effective, but their absence is NOT a sufficient explanation for the
original game termination: BOTH permission states produced the same
self-directed SIGKILL. The precise trigger inside the original
security response is NOT IDENTIFIED. Play Services remain unavailable
and device integrity/certification was not attested.

No playable session, live player coordinates, Unity camera extraction,
or ESP-in-game functionality has been verified. The previous independent
diagnostic overlay was proven on the original loading Activity only.
