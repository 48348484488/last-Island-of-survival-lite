The Android 12/14 comparison reused the **exact independently built APK** from
the previously successful Android 13 run. Thus game inputs, app build,

changed. The app was signed for diagnostics; original Oxide signed APKs
were **not installed** in these experiments.

## True Android compositor pixel validation

Each test starts the independent ARM64 Java app, invokes C++ projection JNI
with a controlled synthetic camera and one test entity, then
draws a transparent green rectangle in an actual
TYPE_APPLICATION_OVERLAY Android WindowManager window.
Following states use missing samples or stale timestamps, then
stop the service and capture an actual device screenshot.

| Native Redroid virtual Android | Fresh pixels | Zero samples | Stale samples | After process stop | Result |
|---|---:|---:|---:|---:|---|
| Android 12 | 2,112 | 0 | 0 | 0 | **PASS** |
| Android 13 | 2,112 | 0 | 0 | 0 | **PASS** |
| Android 14 | 2,112 | 0 | 0 | 0 | **PASS** |

Across all three, the validator confirmed Android Activity launch,
Service PID active during each test case, exactly one corresponding
JNI Service success marker, original-game package absent, and no
diagnostic app-specific AndroidRuntime crash in the captured interval.

Seven validator regression tests passed in each native-Android version.
The Android13 APK build separately passed seven pixel-state and five
existing original-overlay pixel tests.

## Single WindowManager service continuously updates — Android 13

The more demanding follow-up [#38543062941](https://github.com/48348484488/oxide/actions/runs/38543062941)
reused the same service PID without restarting to receive synthetic
position changes and TTL expiry:

| Phase | Green pixels | Rect center X at 720px screenshot width |
|---|---:|---:|
| INITIAL | 2,112 | 359.5 |
| MOVED | 2,112 | 431.5 |
| STALE | 0 | no marker |
| RESTORED | 2,112 | 287.5 |
| STOPPED | 0 | no marker |

The original C++ timed JNI bridge rejected the stale snapshot;
the Service called invalidate() on the same WindowManager View for
updated valid and empty states and automatically removed its window
when stopped. JNI phase markers, measured movement, actual screenshot
pixels, stable PID and stop cleanup all matched.

## Scope and remaining original-game blocker

**Established:** JNI bridge and visual overlay state changes on native
Android ARM64 virtual versions 12, 13 and 14, with legitimate synthetic
inputs, and no observed service crash for these bounded tests.
This is verified using real Android images and screen captures,
not mocked Android or simulated game data.

**Not established:** Original Oxide multiplayer functionality,
original game's camera/view-projection and player data sources,
live opponents or real in-game ESP. The original game was not
installed in these workflows. The original signed Oxide is independently
known to display a security warning and self-terminate on these
Redroid configurations. This work neither removes, bypasses nor
attributes that security decision.

The project should remain **100% virtual**. The next engineering
challenge is real, permitted scene/camera input integration and
proper application compatibility validation, not repeating the
already-confirmed independent overlay draw and removal tests.
