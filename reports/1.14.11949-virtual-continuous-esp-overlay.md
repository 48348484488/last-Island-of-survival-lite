## Actual continuous Service timeline

The one Android WindowManager.TYPE_APPLICATION_OVERLAY Service starts on the
launcher, without original Oxide installed and without reading any
other process. All coordinates are controlled synthetic JNI inputs
processed through the project C++ projection library.
The Handler updates the SAME overlay view without destroying/recreating it:

1. INITIAL: a projected green rectangle at x≈359.5 screen pixels.
2. MOVED: a new camera-input snapshot shifts its center to x≈431.5.
3. STALE: data are older than max_age_ms (600 ms > 250 ms); JNI
   returns zero projected rectangles and green marker pixels fall to 0.
4. RESTORED: a valid new snapshot places its center at x≈287.5.
5. STOPPED: the same Service's window is removed; screenshot has 0
   projected green pixels and Android lifecycle log confirms teardown.

| Captured state | Marker pixels | Marker center X | JNI rectangles |
|---|---:|---:|---:|
| INITIAL | 2,112 | 359.5 | 1 |
| MOVED | 2,112 | 431.5 | 1 |
| STALE | **0** | — | 0 |
| RESTORED | 2,112 | 287.5 | 1 |
| STOPPED | **0** | — | removed |

## What is NOT yet solved

- The original game security warning on native virtual Android 12/13/14
  still blocks original multiplayer loading.
- The isolated APK creates synthetic input snapshots and has no
  authorized original-game player/camera data source.
- Service-scheduled snapshots demonstrate a working **dynamic Android
  overlay rendering pipeline**. They are not a live game feed, ESP
  with actual players, anti-cheat bypass or proof of gameplay.
- No physical device, physical device farm, game patch, identity
  spoofing, process hook or protection modification was used.

## Next engineering focus

Keep original-game startup compatibility separate.
For the independent overlay, introduce a bounded **on-demand
caller-controlled sample feed** into the same running Service,
with strict freshness, timestamp monotonicity and no persistent
stale boxes. Test that feed with Android ADB commands against
the separate diagnostic package in virtual ARM64.
