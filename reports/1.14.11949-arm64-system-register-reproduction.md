# Oxide 1.14.11949 — original ARM64 loader CPU ID and isolated SIGILL reproduction

Date: 2026-10-13. Repository: 48348484488/oxide.

## Grounded evidence

- [Original four-split Oxide on official Android 15 Google Play image](https://github.com/48348484488/oxide/actions/runs/38480303555): installation succeeded; original process PID 4078 failed with native SIGILL (code SI_TKILL) during ARM64 guest constructor execution, with libloader.so guest PCs 0x830BEC and 0x830D98.
- [Original ARM64 libloader static ELF mapping](https://github.com/48348484488/oxide/actions/runs/38483165414): exact signed original libloader.so SHA-256 c272ff0c10833dc6404559b7817d49faff637f5b417d569ee69c75e9ebd2c114; original guest PC 0x830BEC contains the ELF64 little-endian instruction bytes 290438d5 and disassembles to the ARM64 CPU feature read shown below.
- [Independent JNI reproduction on the same official Google Play x86_64 Android emulator](https://github.com/48348484488/oxide/actions/runs/38483564342): BOTH workflow jobs successful (the workflow tests, not original-game startup). Our own separately signed ARM64 diagnostic APK, with no Oxide original game installed, executed a matching ARM64 MRS instruction via JNI.

### Exact original instruction and its caller

    0x830BEC: mrs x9, id_aa64pfr1_el1
    0x830D98: bl 0x8308dc

The first reads the ARM64 ID_AA64PFR1_EL1 system register. The second branches to its containing feature-detection routine; source reconstruction of the full function has NOT been performed.

### Independent reproduction on Android 15 Google Play x86_64 with native bridge

    Diagnostic PID: 2727
    Native bridge: libndk_translation.so
    Stage before MRS: OBSERVED
    Stage after MRS: NOT OBSERVED
    Fatal SIGILL for diagnostic PID 2727: OBSERVED
    Verdict: INDEPENDENT_CPU_ID_MRS_SIGILL_ON_NATIVE_BRIDGE

The independent APK was built by esp_core/android_probe/build_smoke_apk.sh and contained an explicit JNI entry point, nativeReadCpuIdPfr1. It does not import, access, modify or patch any Oxide game process or signature. The crash was reproduced without any game security subsystem loaded.

**What this supports:** the official x86_64 Google Play emulator's ARM64 translation has a demonstrated incompatibility with the independent register-read experiment. This strengthens a plausible link to the original game crash in the ARM64 loader.

**What this does NOT prove:** that the original game SIGILL arose from precisely this one instruction rather than an intentional signal, another loader problem or security response; or that fixing register translation would make Oxide playable. Both original and independent crashes require distinct causal validation.

### Proven native ARM64 comparison

The **same separately signed JNI diagnostic APK**, still without original Oxide installed, also ran on a **native ARM64 Android 13 Redroid** host.

- [Actual native ARM64 run #38483882677](https://github.com/48348484488/oxide/actions/runs/38483882677): success.
- Independent diagnostic PID **1720**, marker BEFORE_MRS logged; marker MRS_RETURNED VALUE=0x0 logged; **no SIGILL**.
- Original x86_64 Google Play Android 15 translated run PID **2727**: marker BEFORE_MRS logged; marker MRS_RETURNED **not** logged; SIGILL for the SAME PID.
- The translated run's **actual raw logcat** records:
  
      10-13 23:22:09.274 2727 2727 I OXIDE_CPU_ID_PROBE: STAGE=BEFORE_MRS_ID_AA64PFR1_EL1
      10-13 23:22:09.275 2727 2727 E berberis: Undefined instruction 0xd5380420 at 0x00007c416e8fa304
      10-13 23:22:09.278 2727 2727 F libc: Fatal signal 4 (SIGILL), code -6 (SI_TKILL)

- The independent crash **guest backtrace explicitly points to**
  liboxide_esp_probe.so `Java_com_oxide_bridgeprobe_MainActivity_nativeReadCpuIdPfr1+0`, demonstrating this was the native JNI experiment, not another process.
- The opcode `0xd5380420` is the same MRS system register instruction as original Oxide's `0xd5380429` at guest PC 0x830BEC, differing only in the destination register field (x0 vs x9).
- [Cross-environment reanalysis run #38484206999](https://github.com/48348484488/oxide/actions/runs/38484206999) passed eight parser tests and validated the Berberis PID, unsupported opcode and native success from the **two actual archived Android logcats**. Result: **ARM64_TRANSLATOR_MRS_INCOMPATIBILITY_REPRODUCED**.

**Interpretation:** this is independent, repeatable evidence of a CPU ID system-register incompatibility in the x86_64 emulator's ARM64 translation. It substantially supports an environment-related reason for the original game's early SIGILL. It does NOT prove that this is the only reason or that correcting it would clear the original game's separate security checks on native ARM64.

The absence of original game APKs in both isolated CPU-ID tests was intentional; there was no game patch, signing change, anti-cheat intervention or Play Integrity verdict.

### Native ARM64 Google Play emulator feasibility

- Official Android SDK lists Google Play ARM64 images for Android 13–16: [SDK and host capability audit](https://github.com/48348484488/oxide/actions/runs/38481155935).
- Native Linux ARM64 GitHub runner has no /dev/kvm.

Android was never connected by ADB and the game was not installed.

None of this verifies a Google Play integrity verdict, game multiplayer launch, real entity positions or a working in-game ESP. All original APKs remained unmodified.


## Final cross-verification: original Oxide itself reports the SAME unsupported opcode

[Original game plus both controls verification run #38484496716](https://github.com/48348484488/oxide/actions/runs/38484496716)
**passed** with 13 Python regression tests (4+4+5). The workflow
downloaded the ACTUAL archived original-game, translated diagnostic and
native ARM64 diagnostic logs; it did not download or run the game again.

Direct original Oxide logcat evidence, process PID **4078**:

    10-13 22:51:45.824 4078 4078 E berberis: Undefined instruction 0xd5380429 at 0x0000713aa1ca7bec
    10-13 22:51:45.825 4078 4078 F libc: Fatal signal 4 (SIGILL), code -6 (SI_TKILL)

Native tombstone from the same original process:

    #00 pc 0000000000830bec .../lib/arm64/libloader.so
    #01 pc 0000000000830d98 .../lib/arm64/libloader.so

Exactly matching the original ELF instruction disassembly:

    0x830BEC: mrs x9, id_aa64pfr1_el1    ; machine code d5380429

Independent translated diagnostic process PID 2727:

    10-13 23:22:09.275 2727 2727 E berberis: Undefined instruction 0xd5380420
    10-13 23:22:09.278 2727 2727 F libc: Fatal signal 4 (SIGILL), code -6 (SI_TKILL)

Its guest tombstone top frame points to
Java_com_oxide_bridgeprobe_MainActivity_nativeReadCpuIdPfr1+0.
The code 0xd5380420 differs from original 0xd5380429 only in the five
destination-register bits, not the system register or operation.
The independent native Android ARM64 process PID 1720 returned 0x0
from the same register read without SIGILL.

**Confirmed immediate cause of the original game's Google Play x86_64
emulator crash:** Berberis failed to translate this ARM64 MRS feature
register instruction in libloader.so. This conclusion is directly
supported by the ORIGINAL process's own Berberis error plus the independent
cross-environment reproduction. It is stronger than a speculative
interpretation of a SIGILL tombstone alone.

**Not resolved:** the original game's separate protection/compatibility
self-SIGKILL observed in the native ARM64 Redroid environment.
Fixing translated ARM64 MRS support would not by itself prove an active
game session or working ESP. No Play integrity verdict, real-player
telemetry or crash-free gameplay was obtained.
