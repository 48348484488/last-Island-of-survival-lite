# Oxide 1.14.11949 — original ARM64 loader CPU ID and isolated SIGILL reproduction

Date: 2026-10-13. Repository: 48348484488/oxide.

## Grounded evidence

- [Original four-split Oxide on official Android 15 Google Play image](https://github.com/48348484488/oxide/actions/runs/38480303555): installation succeeded; original process PID 4078 failed with native SIGILL (code SI_TKILL) during ARM64 guest constructor execution, with libloader.so guest PCs 0x830BEC and 0x830D98.
- [Original ARM64 libloader static ELF mapping](https://github.com/48348484488/oxide/actions/runs/38483165414): exact signed original libloader.so SHA-256 c272ff0c10833dc6404559b7817d49faff637f5b417d569ee69c75e9ebd2c114; original guest PC 0x830BEC contains the ELF64 little-endian instruction bytes 290438d5 and disassembles to the ARM64 CPU feature read shown below.
- [Independent JNI reproduction on the same official Google Play x86_64 Android emulator](https://github.com/48348484488/oxide/actions/runs/38483564342): BOTH workflow jobs successful (the workflow tests, not original-game startup). Our own separately signed ARM64 diagnostic APK, with no Oxide original game installed, executed a matching ARM64 MRS instruction via JNI.

### Exact original instruction and its caller

    0x830BEC: mrs x9, id_aa64pfr1_el1
    0x830D98: bl 0x8308dc

The first reads the ARM64 ID_AA64PFR1_EL1 system register. The second branches to its containing feature-detection routine; source reconstruction of the full function has NOT been performed.

### Independent reproduction on Android 15 Google Play x86_64 with native bridge

    Diagnostic PID: 2727
    Native bridge: libndk_translation.so
    Stage before MRS: OBSERVED
    Stage after MRS: NOT OBSERVED
    Fatal SIGILL for diagnostic PID 2727: OBSERVED
    Verdict: INDEPENDENT_CPU_ID_MRS_SIGILL_ON_NATIVE_BRIDGE

The independent APK was built by esp_core/android_probe/build_smoke_apk.sh and contained an explicit JNI entry point, nativeReadCpuIdPfr1. It does not import, access, modify or patch any Oxide game process or signature. The crash was reproduced without any game security subsystem loaded.

**What this supports:** the official x86_64 Google Play emulator's ARM64 translation has a demonstrated incompatibility with the independent register-read experiment. This strengthens a plausible link to the original game crash in the ARM64 loader.

**What this does NOT prove:** that the original game SIGILL arose from precisely this one instruction rather than an intentional signal, another loader problem or security response; or that fixing register translation would make Oxide playable. Both original and independent crashes require distinct causal validation.
